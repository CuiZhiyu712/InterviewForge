# 全量面试题答案数据库设计

## 目标

将当前抓取的 1,200 条公开题目与文章型标题全部转换为可刷题内容。SQLite 作为唯一结构化数据源，构建脚本从数据库生成无需服务器、可双击使用的单文件 HTML。

## 范围与边界

- 覆盖 `data/source-index.json` 的全部 1,200 条记录，包括明确问句和文章型标题。
- 文章型标题转换为对应的知识讲解题，例如“Redis 持久化详解”转换为“请介绍 Redis 的持久化机制”。
- 答案独立撰写，不复制来源正文、图片、付费内容或长段落。
- 每道题保留精确来源 URL，用于题目溯源和延伸阅读；来源不代表答案引用。
- 原有 87 道核心题并入数据库，保留其简历优先级与经过复核的答案。

## 数据库

文件：`data/interview_bank.sqlite`

### questions

- `id`：内部唯一 ID。
- `source_id`：对应来源索引 ID，唯一。
- `question`：规范化后的面试问题。
- `original_title`：公开页面中的原始标题。
- `module`、`submodule`：知识模块。
- `difficulty`：基础、中等、进阶。
- `source_site`、`source_url`：精确来源。
- `resume_focus`、`priority`、`resume_reason`：简历重点信息。
- `context_note`：题意依赖面经上下文时的说明。

### answers

- `question_id`：一对一关联题目。
- `short_answer`：一句话结论。
- `full_answer`：可口述 1–3 分钟的面试回答。
- `pitfalls`：易错点或回答边界。
- `answer_origin`：固定标记为原创整理。
- `review_status`：draft、checked、priority-reviewed。

### follow_ups

- `question_id`、`position`。
- `question`：追问。
- `answer`：追问的简短答案。

### tags

- `question_id`、`tag`，使用联合唯一约束。

### answer_reviews

- `question_id`、`batch`、`status`、`notes`、`reviewed_at`。
- 保存批次与检查结果，不保存模型内部推理过程。

## 答案规范

每道题必须包含：

1. 一句话结论，直接回答问题。
2. 完整回答，优先使用“定义—机制—取舍—应用”的结构，长度以 1–3 分钟口述为准。
3. 两到三个追问，每个追问都有答案。
4. 至少一个易错点，指出绝对化表述、适用边界或常见混淆。
5. 精确来源链接和原创答案标记。

重复或近似题允许共享相同知识事实，但必须针对当前问法组织答案。公司面经中上下文缺失的问题使用通用技术语境回答，并通过 `context_note` 明示假设。

## 简历重点

- 读取 `data/resume-focus.json` 的 P0/P1/P2 主题和关键词。
- P0：求职定位、真实性、Java 实习链路、RAG、Agent、Tool Calling/MCP、运维证据链、求职业务闭环、大模型故障与安全。
- P1：Java 并发、Spring Boot、MySQL、Redis/MQ、Milvus、会话记忆、SSE、可观测性。
- P2：Transformer 基础、声波与 IMU 项目、应用算法成长路线。
- 重点题除了通用答案，还要在 `resume_reason` 中说明与当前简历的关系；不得把未实现功能写成成果。

## 内容生产与检查

答案按相互独立的领域批次编写：Java/JVM/并发、数据库与缓存、网络与操作系统、Spring/分布式/MQ、LLM/RAG、Agent/框架/工程。每个批次输出结构化记录，再统一导入 SQLite。

自动检查包括：

- 来源覆盖率必须为 1,200/1,200，`source_id` 无重复。
- 所有必填字段、追问答案和易错点非空。
- 检测答案过短、完全重复、占位符和模板残留。
- 所有 URL 必须与来源索引逐项一致。
- 模块、难度和优先级只能使用约定枚举。
- SQLite 外键与唯一约束通过完整性检查。

人工/独立复核优先检查 P0/P1 题、简历项目题、容易过时或存在技术争议的答案，以及自动检查发现的近似答案。

## HTML

- 页面显示全部 1,200 道完整问答，不再把未作答条目放在独立来源目录。
- 答案默认折叠；追问答案使用二级折叠。
- 支持模块、子模块、难度、P0/P1/P2、学习状态、收藏和全文搜索。
- 支持随机刷题、上一题、下一题以及仅抽取不会/模糊题。
- `localStorage` 保存学习状态；存储不可用时仍能在当前会话操作。
- 构建脚本查询 SQLite 并把数据序列化到 HTML；最终文件不依赖网络脚本、CSS、字体或数据库驱动。

## 错误处理

- 导入时发现重复或缺失来源即停止，不部分写入数据库。
- 批次答案校验不通过时拒绝导入，并输出具体题号与原因。
- 构建前运行 SQLite 完整性、覆盖率和内容质量检查。
- 浏览器端遇到损坏的本地学习记录时回退为空状态，不影响题库加载。

## 验收条件

- SQLite 中恰有 1,200 道题、1,200 条答案，每题有 2–3 个带答案的追问和至少一个易错点。
- 题目与 `source-index.json` 一一对应，并保留精确来源链接。
- 全部自动化检查通过，P0/P1 复核无 Critical 或 Important 问题。
- 最终单文件 HTML 可展示和检索全部 1,200 道题，答案默认折叠，所有刷题与状态功能可用。
- 数据库、构建脚本、HTML、质量报告和说明文档提交并推送到远程仓库。
